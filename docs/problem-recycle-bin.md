# 跳过与可恢复的回收站

> **开发参考** · [开发文档索引](development/README.md) · 日常操作请看[用户手册](user/README.md)。本文保留既有地址，供实现与排错核对。


出题测试题、私有题或已删除的题目可能没有题面，不需要为它们填写虚构内容。

进入「账号与同步」，选择洛谷账号，展开「待补题目与手动处理 · 已跳过 / 回收站」。里面提供三个页签：

| 操作 | 补题面队列 | 本地题库与统计 | 后续同步 | 恢复 |
| --- | --- | --- | --- | --- |
| 跳过 | 从该来源各账号队列中移除 | 保留已有题目、做题记录与统计 | 继续导入历史，但不再补齐此题资料 | 在「已跳过」恢复 |
| 移入回收站 | 从该来源各账号队列中移除 | 隐藏题目，排除对应提交和复盘的统计、能力评估输入与新训练选题 | 原始记录可以更新，但不会重新显示或排队 | 在「回收站」恢复 |
| 恢复 | 若题面仍缺失，加入当前账号的待补队列 | 恢复使用保留的原始记录 | 恢复正常行为 | 无物理清空操作 |

每行可以单独操作，也可勾选本页后批量操作。跨页不保留选择，每次最多 50 题。确认区域列出具体题号与影响范围，状态变化时整批拒绝，刷新后重新选择。回收站和已跳过列表每页 20 项，提供首页、前后页和末页。

决定以**本地原生题目键**保存，同一洛谷来源的所有账号共用。CF 等其他来源的同题记录独立保留；合并题库不再用被删除的洛谷记录提供 AC 证据，仍可展示其他来源的有效题目。

操作只写本地数据库，不改动洛谷网站，不调用 AI，也无需 Cookie。同步运行时先暂停，其他实例持有同步租约时会拒绝，避免并发写入丢失决定。恢复需要队列空间；队列满时保持原状态并显示原因，不部分恢复。

旧的 AI 评估报告和已生成计划保留为历史快照，需重新生成来反映当前数据。账号级官方比赛评分与手工虚拟表现分不是这些题目的提交记录，不受回收站影响。

数据库 v10 新增 `problem_dispositions` 表，保留原始题目、提交、快照与复盘行。升级前自动生成可验证的旧版备份，旧版本插件拒绝新库；卸载插件不清空数据。清除 tombstone 只发生在显式恢复操作中，平台导入不会自动恢复。

API：`luogu.managedProblems` 读取有界恢复列表；`luogu.manageProblems` 接收显式题目键、预期状态和 skip/trash/restore 动作。UI 经宿主鉴权的业务 API 调用，后台事务同时保存状态及所有相关队列修改。

# 题库：浏览、筛选与状态管理

「题库」有两个视图，用页面顶部的标签切换：

- **分平台题库**：按具体平台浏览、导入、审核与选题，在这里按所选平台账号修改完成方式。
- **合并题库（跨站去重）**：把已导入的各平台题目放在一起浏览，并按所选账号联动显示通过状态。合并浏览本身不下载数据，也不调用模型。

## 分平台题库

- **搜索**：按题号或标题搜索。
- **排序**：题号升序/降序、题目名称升序/降序、难度从低到高/从高到低。题号按自然数字顺序排列（`2A` 在 `10A` 前），难度按所选平台的**原生维度**比较，缺失或非数值始终排在末尾，手工来源可以指定维度。排序先作用于全部筛选结果，再分页。
- **状态**：`全部` / `已通过` / `未确认通过`。未选择当前账号时通过状态无法判断，选择器会被禁用并说明原因。
- **仅看该账号尝试过的题**：可与状态筛选叠加。
- **显示列表中的算法标签**：控制列表里是否显示标签，默认关闭。
- **每页**：25 / 50 / 100；列表上下都能翻页，支持首页、末页与页码跳转。总数按当前筛选下的本地目录计算。
- **刷新**：重新读取当前筛选结果。

### 合并题库（跨站去重）

- **哪些题会合并**：当前自动识别官方 Codeforces 主站题号与洛谷对应的 CF 镜像编号，例如 **CF 1A ↔ 洛谷 CF1A**。同一组在总数与分页中计为一道题，同时保留每个站点的题号、名称、原题链接与难度；两站难度独立展示，难度排序需要先选择具体平台。
- **哪些题不会合并**：不同题号的同名题、E1/E2 等不同版本、Gym 题，以及尚无明确映射的题目仍分别显示。当前**没有**任意两题的手工合并，也没有基于相似标题的自动推断。
- **通过状态从哪里来**：为参与统计的每个平台最多选择一个账号（其他已保存账号的成绩不会自动参与）。一组题在所选任一账号上有真实 AC，就显示「已通过」，并注明账号、平台、题号和提交时间。重复 AC 只产生一个通过状态；后来的 WA 不会撤销已有 AC。即使 AC 所在站点的题目信息尚未导入，只要原始提交记录存在且编号能明确关联，也能提供通过依据。
- **「本平台已通过」与「关联题目已通过」**：分别表示原站 AC 与跨站关联结果。联动只是本地浏览视图：不会写入另一平台的提交记录、不会替你提交代码，也不修改原始成绩。打开某站题目详情时，提示与复盘使用该站点所选账号，不会套用其他平台账号。
- **原始资料各归各站**：原始标签、题解、分析快照与人工决定仍属于各站题目；关联 AC 不会自动采用另一站的标签，也不会自动公开未通过站点的题解。正式薄弱项与训练计划沿用各账号自身的原始记录。
- **浏览与筛选**：支持搜索任一成员题号或标题、筛选已通过/未确认通过、仅看尝试过的题、题号与名称排序，以及首页/末页/页码跳转；计数是当前筛选下的合并组数。筛选某个平台时，显示包含该平台题目的组，仍保留所选其他平台账号提供的同题 AC 依据。
- 导入和同步需要明确的数据来源：点「导入 / 同步各平台数据」回到分平台题库。**批量修改完成方式也要切到「分平台题库」**并选择该平台账号后进行，合并题库只做跨站浏览与通过联动。

## AC 证据 ≠ 独立完成

平台上的「已通过」是**外部证据**：它说明平台记录了一次通过的提交，不说明你是否独立想出了解法。列表和详情里的 AC 不会自动变成“掌握”：

- 没有复盘记录的题目显示「未标注」，独立性保持**未知**（既不是独立完成，也不是未独立完成）。
- 只有复盘 / 完成方式记录能标注 **独立完成**、**使用提示完成** 或 **参考题解完成**；统计与 AI 评估按这三类分别计数。
- 合并题库里的关联 AC 也不会把“已通过”变成“独立完成”，更不会改写另一站的记录或标签。

打开题目详情后，可以展开「标签与来源」「查看当前分析与证据」「粘贴外部答案 / 用户提供解析」等区域；标签与证据的含义见[标签与题解材料](tags-and-answers.md)。

## 题面与 Markdown 渲染范围

在「题库」打开一道题并展开题面即可查看排版结果；保存的题解与 AI 提示正文使用同一渲染器。点击伸缩栏标题展开或收起，代码块右上角可复制，底部「查看原文」保留**未修改的原始字符串**。

支持的能力（语法按洛谷公开 Markdown 规则独立实现）：

- CommonMark/GFM 基础排版、表格、列表、引用；
- 数学公式（KaTeX；无效公式保留原表达式）；
- 折叠块 `:::info[标题]{open}`（以及 `success` / `warning` / `error`；只有 `open` **存在**时默认展开）；
- 对齐 `:::align{center}`、题记 `:::epigraph[作者]`、`::cute-table{tuack}` 表格装饰；
- GFM 表格里的 `^`（向上合并）与 `<`（向左合并）单元格标记，未完整成矩形时保留可见标记；
- 代码围栏 meta：`line-numbers` 与 `lines=2-4`（行号在代码之外，复制仍是精确代码）；
- 可识别的 Bilibili 视频/播放器页面图片链接会渲染成安全外链按钮「打开视频：…」。

明确不支持或会降级的行为：

- **不解析 raw HTML**：`<details>`、`<img …>`、`<script>` 等按普通文本显示，原文入口里仍然完整。
- 不嵌入 Bilibili 播放器、不加脚本、不自动播放、不向 B 站发起请求；点击只在新标签页打开原页面。短链、空间页与仿冒域名按普通图片处理。
- 未知指令（如 `:::mystery`）保留完整源文本；`:::align` 只认 `center` / `right`，其他取值按未知指令显示字面标记。
- 超过 250000 字符的文本不渲染，改为完整原文加提示；行号/范围高亮超过 5000 行时不显示行号（代码仍完整）；深于 12 层、超过 20000 节点、超过 200 行或 2000 单元格的表格保持原样，不做部分变换。
- 渲染过程不调用 AI、不访问存储、不发起任何网络请求；查看已有内容不消耗 AI 额度。

更细的语法与边界（包含旧格式样例的兼容规则）见[技术参考：本地 Markdown 渲染](https://github.com/UnivmemorN/dsh-icpc-workbench/blob/main/docs/markdown-rendering.md)。

## 每行与整页批量修改完成方式

完成方式记录“这道题你是怎么完成的”，它影响知识点统计与规则能力评估，但不改变平台记录。

1. 在「题库 → 分平台题库」选择当前账号；可以先筛选「已通过」并把每页数量调到 100。
2. **整页勾选**：点表头的复选框（本页全选后它是勾选状态，只选了一部分时显示为中间横线），或用表格上方工具栏的「全选本页」。工具栏在滚动长列表时固定在顶部，表格下方也有一份同样的操作，并实时显示「本页已选 N / M」与「已选择 N / 100（跨页保留）」。本页已全选时，点表头复选框或「取消全选本页」只取消本页，其他页的已选保持不变；「取消本页」也只移除当前页的勾选，「清空选择」才放弃全部。
3. **只选还没标注的题**：点「选择本页未标注」，它只选中最新记录为空的题目（平台 AC 不会当作已有记录）。未选择账号时仍可勾选题目，但不能打开批量修改。
4. 单题点该行的「修改」；批量勾选后点工具栏的主按钮「批量修改完成方式」（编辑区就在表格上方，不会跳到 100 行之外）。
5. 选择 `独立完成` / `使用提示完成` / `参考题解完成`，点「预览修改」，核对逐题变化后保存。编辑区的「当前完成方式」和预览里的「逐题明细」在批量编辑时默认折叠成一行，点标题行即可展开逐题核对；汇总的会改变/无变化题数与清除题解提示始终显示。

规则与保留内容：

- 选择可以跨页保留，**每批最多 100 题**；界面会显示「本页已选 N / M」和「已选择 N / 100」。达到上限时，本页多余的题目不会加入，界面会说明有多少行没有加入；其他页面已选中的题目不会被丢弃，也不会重复计数。
- 列表正在读取、刷新或读取失败时，整页与逐行勾选会暂时禁用，避免对旧页面的数据操作；「选择本页未标注」还要等完成方式读取成功后才可用。选择提示显示在工具栏内（顶部和底部各一份），不会只留在页面末尾。
- 默认保留已有备注、已确认知识点与参考题解引用；改成「独立完成」时，预览会明确列出将清除的参考题解引用数量。
- 如果所选题目确实都用了相同知识点，可以勾选「同时补充实际使用的知识点」并手动选择；已有知识点不会重复添加。需要逐题调整知识点或备注时，在题目详情展开完整复盘表单。
- 编辑不会改变平台 AC 记录，也**不会确认题目标签**；只改完成方式不会把题目的全部标签计为已掌握。
- 修改后，本地知识点统计和规则能力评估读取最新记录；**历史 AI 报告保留生成时的结果**，需要主动重新准备与生成评估。
- 编辑完成方式与查看本地统计都不调用 AI。
- 合并题库中的镜像题仍属于各自平台账号，批量编辑在分平台题库进行。

## 跳过、回收站与恢复（题库视角）

平台不提供题面的题目（出题测试题、私有题、已删除的题目等）可以跳过补齐或移入回收站，不需要填写虚构题面。操作入口在「账号与同步 → 洛谷账号 → 待补题目与手动处理 · 已跳过 / 回收站」，三个页签为**待补题目**、**已跳过**、**回收站**。

| 操作 | 对补题面队列 | 对本地题库与统计 | 对后续同步 | 恢复方式 |
| --- | --- | --- | --- | --- |
| 跳过 | 从该来源各账号队列移除 | 保留已有题目、做题记录与统计 | 继续导入历史，但不再补齐此题资料 | 「已跳过」页签 |
| 移入回收站 | 从该来源各账号队列移除 | 隐藏题目，并从对应提交与复盘的统计、新能力评估输入、新训练选题中排除 | 原始记录可以更新，但不会重新显示或排队 | 「回收站」页签 |
| 恢复 | 题面仍缺失时回到当前账号待补队列 | 恢复使用保留的原始记录 | 恢复正常行为 | 无物理清空操作 |

- 每行可单独操作，也可勾选本页批量操作；跨页不保留选择，每次最多 50 题；确认区域列出具体题号与影响范围，状态变化时整批拒绝，刷新后重新选择。
- 已跳过/回收站列表每页 20 项，提供首页、前后页与末页。
- 同一个洛谷站点上，该题的处理状态由所有本地账号共用；CF 等其他来源的同题记录独立保留。合并题库不再用被移入回收站的洛谷记录提供 AC 证据。
- 操作只修改本地记录，不改动洛谷网站、不调用 AI、也不需要 Cookie。同步正在运行时需要先暂停；其他 dsh 实例正在同步时会拒绝操作，请等待其完成。恢复需要队列空间，队列满时保持原状态并显示原因。
- 旧的 AI 评估报告与已生成计划保留为历史快照，需要重新生成才能反映当前数据；账号级官方比赛评分与手工虚拟表现分不是这些题目的提交记录，不受回收站影响。

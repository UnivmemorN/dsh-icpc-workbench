# 知识点与能力

「薄弱项」页面回答两个不同的问题：**知识点层面我有哪些证据**，以及**我现在的水平参考是什么**。本页说明这两块各自的口径、来源和限制。

## 知识点掌握情况

入口：薄弱项 → 知识点掌握情况。

- 列出当前插件词表的**全部**知识点，包含没有观察记录的知识点；可按知识点名称/别名、类别与状态筛选并翻页。
- 每个节点提供经过核对的 **OI Wiki 学习链接**（见下）。
- 同一页面里，**平台标签参考（未复核）**、**已采用标签**、**实际方法（复盘）**分别展示，不合并成一句结论。

### 三类证据与状态

| 证据 | 来源 | 能说明什么 |
| --- | --- | --- |
| 平台参考（未复核） | 平台原始标签经过带来源与版本的对照规则 | 只描述可能相关的尝试/通过题目；歧义、复合、粒度不符的标签保留待核对或只落到更宽的分类 |
| 已采用标签 | 当前有效标签（含过期分析排除规则） | 题目材料中有依据的方法；**仍不能说明你实际采用了它** |
| 实际方法 | 当前账号已 AC 题目的**最新复盘** | 分别计入独立完成、使用提示、参考题解 |

状态是透明的启发式规则，不是校准过的掌握概率：

- **无记录**：没有观察到证据，不等于不会；某个难度没有记录时显示「暂无记录」，不会借用别的难度证据。
- **待确认解法**：已有相关题目但还没有复盘。
- **独立练习中**：有 1–4 道独立完成记录，或只有辅助完成记录。
- **已有独立证据**：至少 5 道独立完成记录。达到阈值也不代表所有难度或整个大类都已掌握。

其他统计口径：

- 按**不同题目**计数；同一题重复提交或修改复盘不会重复累加；后来的 WA 不会撤销 AC。
- 类别只作去重汇总，子节点的证据只向上汇总，大类证据不会向下分发；同一道题不会因多个子标签重复计数。
- 只有所选账号的记录进入统计。
- 查看与筛选本地证据**不调用模型**，也不写入训练记录。

### 平台标签与待核对入口

从 0.1.25 起，官方洛谷的编号标签会通过内置字典解析名称，并参与知识点的「平台参考（未复核）」统计。
旧记录无需重新导入，在薄弱项点击「刷新统计」即可；例如树状数组可以关联具体知识点，动态规划大类只关联分类。

页面上方的「待核对来源标签（全部难度）」保留暂时无法确定映射的标签。点击「查看待核对标签」，
可查看原始标签、未匹配或歧义原因，以及该标签对应的通过/尝试题数。CF 的 `divide and conquer`、
`hashing` 等标签即使没有确定映射，其题目记录仍会保留，同题其他已映射标签仍正常参与统计。
这里汇总全部难度，不随上方难度档位缩减；同题可以有多个标签，各行题数不能相加。
标签关联并不确认你实际采用的解法或独立掌握程度，整个查看过程不调用 AI。

### 难度分层

在「知识点掌握情况 → 难度范围」里选择档位（默认“全部难度（汇总）”）：

- **Codeforces** 按每 **200 分**一档，例如 800–999、1000–1199。这只是本产品的展示分档，不是官方能力等级。
- **洛谷** 保留 1–7 原生等级；`0`、缺失与无效等级放入「未知 / 未评级」。
- **其他来源**保留原生维度及数值或文本等级；来源实例、题目域与不同维度分别统计、不换算。多维度题目会出现在各维度中，**不能跨维度相加**。
- 选择档位后，状态分布、分类汇总、搜索结果、排序与计数都在该档内计算；切换难度回到第一页，切换账号重置筛选。
- 阈值按档独立计算：例如 800–999 有 4 道独立题、1000–1199 有 1 道，汇总达到 5 道，但两档仍各自显示「独立练习中」。低难度记录不证明高难度能力，未知难度中的独立记录也不能证明某个已知难度。

## 历史记录与练习分布

「能力评估」默认并列显示三份评估，全部做题记录放在首位：

| 范围 | 使用的记录 |
| --- | --- |
| 全部做题记录 | 所有已导入、时间不晚于评估时刻的通过记录 |
| 最近 90 天新通过 | 首次已知 AC 落在最近窗口内的题目 |
| 90 天以前通过 | 首次已知 AC 早于最近窗口的题目 |

- 时间窗口使用配置值；旧题重复 AC 不会刷新首次通过时间，同一题只算一次。近期样本充足时，另外两份评估仍然计算，不是兜底。
- 每期先排除最新复盘中已知使用提示或参考题解的题目，再排除其余缺失或无效难度的题目；其余题目参与该期估计，**无复盘的 AC 保持“是否独立未知”**。
- 每期显示通过数、有效样本、有效独立记录、排除数与缺失数，三类数相加等于通过数。
- Codeforces 至少 **5 道有效题**才给出该期的难度中位数（取整到 100）和样本 P25–P75 范围；不足或没有记录时显示不足/无记录，不借用别期分数。洛谷等级 0 不作有效难度；其他平台只呈现原生维度分布，不换算成 CF。
- 这些是**描述性练习分布，不是选手实力**：记录未导入或缺少难度时，系统无法补出证据；近期中位数降低也可能只是你选了更容易的题，不能直接认定退步。

## 官方 CF 评分、历史最高分与个人自评

入口：薄弱项 → 能力评估 → 「同步 CF 评分」与「个人水平校准」。

- **同步 CF 评分**读取 Codeforces 的公开评分资料，**不调用模型**。网络或响应错误不会变成“未评级”，同步失败会保留最近一次成功快照和时间并显示错误。
- **自动分的定义是 CF 官方当前 rating**，按官网原值展示，不取整，也不混入练习中位数或历史最高分。真正的零分或负分按官网原值显示，与未评级不同。
- **历史最高 rating、参赛数与比赛明细**单独展示；最近一场评分在 90 天前会标明历史记录较旧，不会自行扣分，也不会把最高分替换成当前分。
- **个人水平校准**：填写 CF 水平下限、上限并保存。范围标明“用户自评”，按当前账号持久保存，导入与评分同步都不会覆盖它。没有校准时显示「个人水平待校准」；清除自评同样记录新版本，不抹去历史。
- 选题时用户自评优先；没有自评或已清除时，使用已同步的官方当前 rating 作为起点；官方未评级且没有自评时，水平保持未知并安排跨难度诊断。
- 从 0.1.10 起，**不再用练习难度中位数推断个人水平**：选题有偏差，练习也缺少比赛时间限制与独立完成证据。当前没有经过验证的“自由练习 → rating”模型，也没有洛谷/牛客到 CF 的自动换算。

## 虚拟参赛表现（手动录入，非官方）

Codeforces 官方 API 没有 performance 字段，本插件目前采用用户录入的表现分及其来源。你可以在能力评估里手动录入自己的虚拟参赛表现：

- 字段：比赛编号、参赛日期、分数、**计算方法（必填）**、来源链接、独立性与赛前是否见过题；名次与本地备注可选。
- 每项会注明“用户录入”，并与官方 rating 分开展示。
- performance 的定义取决于工具（例如“使 rating 变化为 0 的那个 rating”），所以计算方法是分数的一部分，页面与模型都会把它当作分数的一部分。
- 来源链接只是引用：插件不会抓取，也不接受带用户名/密码的 URL。
- 上限 200 行，按比赛编号去重；重复比赛、越界分数、过去日期以外的日期与非法 URL 会在写入前拒绝。
- 当前**不会自动计算**虚拟 performance，需要你从使用的工具录入结果。
- AI 评估可以结合“有来源、明确独立且赛前未见题”的虚拟表现与官方比赛分给出带置信度的推断范围，但不会改写官方分。

## OI Wiki 与牛客的角色

- **OI Wiki**：每个知识节点附带学习链接，部分复合知识点对应多篇资料，宽泛映射标注「参考概述」。OI Wiki 是**学习资料目录**，不是 OJ、不是考纲，也不认证掌握程度；本项目只提供主题名称、链接和独立编写的映射规则，不内置其文章、示例代码、图片或题库，也不计划为它提供题目/提交导入。
- **牛客 ACM 知识点练习**：分类浏览、知识点搜索与练习统计的展示方式参考了它的公开页面；本项目独立设计证据分层与状态规则，**不复制**其页面、代码、题库或账号数据，状态也不是牛客的官方评价。牛客术语目前只参与标签对照规则，尚无牛客导入适配器。
- 两处引用同时出现在知识点页面与 [THIRD_PARTY_NOTICES](../../THIRD_PARTY_NOTICES.md)；本项目与它们没有合作、认证或官方关联。

## 不调用模型的部分

知识点统计、难度分层、历史分布与自评保存在本地处理，评分同步会读取 CF 公开数据；这些操作**不调用 AI、不产生费用**。只有显式生成 AI 能力评估报告或训练计划时才会调用模型，见[训练计划与能力评估](training-and-assessment.md)。

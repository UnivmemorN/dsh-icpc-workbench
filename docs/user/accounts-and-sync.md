# 账号与同步

「账号与同步」页面管理平台账号、导入题目目录与提交记录，并承载洛谷的账号连接与历史同步。页面上的「数据来源」跟随当前选中的账号。

## 添加账号（只保存公开标识）

展开「添加账号」，选择平台并填写标识；也可以直接粘贴公开个人主页链接，界面会说明格式：

- **Codeforces Handle（用户名）**：个人主页 `https://codeforces.com/profile/tourist` 里的 `tourist` 就是 Handle。请填写自己的用户名。
- **洛谷 UID（数字用户号）**：打开自己的洛谷个人主页，复制网址 `/user/` 后面的数字，例如 `https://www.luogu.com.cn/user/123456` 中的 `123456`。它与可修改的**昵称**不同，账号身份始终是 UID。

添加账号只保存公开标识，不需要密码，也不代表立刻有做题记录。没有账号也可以同步公开题目目录或手工导入；但同步“所选账号的提交记录”需要先有对应平台的账号。

### 洛谷公开昵称

洛谷账号可以显示公开昵称（例如「示例昵称 · UID 123456 · 洛谷」）：

- 进入账号页或选中洛谷账号时，会**自动尝试一次**读取；也可以点「刷新洛谷昵称」手动重试。
- 这次读取是公开、匿名的：不需要 Cookie、不调用 AI、不改动做题记录，也不读写登录凭据。
- 昵称只是显示名称；账号身份仍是 UID。没有可用的公开昵称时显示「洛谷用户」，UID 始终单独展示，不会把昵称当成 UID。
- 读取被限流或与同步冲突时会失败并提示；「账号已添加，昵称暂未获取」只表示昵称没取到，绑定已经保存，稍后重试即可，不需要重新添加账号。

## 导入与同步公开数据

在「账号与同步 → 导入与同步 → 从平台同步公开数据」里：

- **数据类型**：`题目目录`（公开题目列表与元数据）或 `所选账号的提交记录`。
- **开始同步 / 继续上次进度 / 从头重新同步**：按进度断点续传；需要中止时点「取消请求」。
- 插件对 Codeforces 同一来源的请求至少间隔 2 秒，等待排队即可。
- 手工材料（JSON/CSV、题面、题解、用户提供解析）走「导入 JSON / CSV 文件或粘贴材料」，见[手工导入](manual-import.md)。

## 连接洛谷并同步提交记录（Windows）

洛谷的提交历史需要登录会话。展开「连接洛谷」（已有连接记录时显示「更新登录凭据」）后：

1. 在你平时使用的浏览器里登录洛谷。
2. 按 F12 → **Application（应用程序）→ Storage → Cookies → https://www.luogu.com.cn**。
3. 找到 **`__client_id`**，只复制 **Value（值）** 一列，粘贴到「`__client_id` 的值」输入框。
4. 核对表单上方只读的 **`_uid`** 与浏览器 Cookie 中的 `_uid` 一致；不一致说明当前账号选错了，先切换账号。
5. 点「连接」保存；输入框会在提交、切换账号、切换输入方式、关闭表单或离开页面时清空。
6. 「检查登录」会用已保存的凭据做一次真实读取，确认当前是否可用。

也可以勾选「高级：粘贴整段 Cookie」从 F12 → Network → 请求标头复制完整 Cookie；程序只保留 `__client_id` 与 `_uid` 两项，其余丢弃。**规范化不等于绕过平台校验**：即使凭据有效，平台仍可能要求人工验证或直接拒绝访问，界面会按固定错误码说明。旧版本保存过的整段 Cookie 仍然可用，会在本地按同一规则规范化，不需要为了兼容重新连接。

关于凭据：

- 凭据只发送给本机 dsh 的洛谷连接操作，保存在 **Windows 凭据管理器**（按数据目录隔离的命名空间），不会写入 `localStorage`、设置、备份、日志或 AI 请求。
- **不要把 Cookie 或 `__client_id` 粘贴到 AI 对话、聊天群或任何在线服务**：那等于把账号登录权交给对方。插件从不把登录材料送进模型请求。
- 「断开连接」只删除本机保存的登录凭据；已经同步到本地题库的题目、提交记录、材料与统计全部保留。
- 没有受支持凭据后端的系统（例如 Linux）会把「连接 / 检查登录 / 断开」标为不可用，其余功能不受影响。

## 同步语义：做了什么，不做什么

| 操作 | 实际语义 | 调用 AI？ |
| --- | --- | --- |
| 开始 / 继续同步 | 有未完成进度就从断点继续；否则按最近窗口增量拉取。一轮最多提交 20 页（每页 50 行）与 **100 条题目资料**，剩余留给下一次 | 否，也不消耗 AI 额度 |
| 补齐全部积压资料（不使用 AI） | 只处理点击时已经存在的**题目资料**积压：逐个匿名请求公开题目数据，开始时已有的积压每题只尝试一次；不读取提交历史，不改动历史覆盖、检查点、自动同步设置与计划；每个请求之间至少间隔 2 秒，积压大时可能需要几十分钟 | 否 |
| 全历史完整核对 | 显式重新扫描该账号的全部历史（需要先勾选确认），完成后更新「历史覆盖」 | 否 |
| 暂停本轮 | 只暂停当前这一轮，已完成的进度保留，可稍后继续；不会关闭自动同步 | 否 |
| 自动同步设置 | 按账号决定以后是否自动运行；默认关闭，与「暂停本轮」互不替代 | 否 |

「自动同步设置」的细节：

- 可以设置「启动时同步一次」与间隔（5–1440 分钟）；若设置已在别处修改，按提示刷新后再保存；每账号设置立即生效。
- 自动同步**只在 dsh 打开时**运行：宿主每 60 秒检查一次到期账号，关闭 dsh 后不会同步。
- 修改全局平台限速需要**重启 dsh** 才对洛谷来源生效。

「开始 / 继续同步」是第一步补齐历史：没有检查点就从头开始历史回溯，只有在一次完整的全历史扫描完成后才转入最近窗口增量。增量窗口 = 上次成功扫描开始时间减去 **7 天重叠**，用来刷新刚发生改判的记录；更早以前的重判不会被增量发现，需要显式做一次「全历史完整核对」。完整核对不会删除已有记录。

面板把三种事实分开显示（完整说明在「同步详情」里）：

- **历史覆盖**：是否完成过一次全历史核对；
- **最近一次尝试**：失败码、失败时间、重试时间；
- **题目资料积压**：还没补齐资料的**题目键**数量、已补与失败数。积压与“是否有提交记录缺失”是两件事。积压上限为 2000 条，达到上限会先停止拉取新历史页而不是丢弃题目键。

同步详情中的处理计数表示**处理过的行**，包含重复核对与平台重判复查，**不代表新增提交或新增通过**。平台上的「已通过」是外部证据，不等于你独立掌握了解法。

## 同步失败与逐题处理

一轮同步分两步：先读取**提交记录**（认证请求），再补齐**题目资料**（公开题目数据，匿名读取）。两步可能返回同一个错误码，所以失败记录会保存**失败环节**：

- **读取提交记录**：失败发生在读取提交记录这一步。若错误码是 `auth_required`，先点「检查登录」核对当前登录，再按提示手动继续。
- **补齐题目资料**：失败发生在补齐题目资料这一步。这**不代表**保存的登录凭据已过期，重新连接也不能解决它；已同步的提交记录、历史覆盖与检查点都会保留，待补题目继续排队，可以稍后手动继续。自建或私有的 U / T 类题目可能无法匿名读取（U / T 编号不意味着题目一定私有），受限题保留待补并继续处理其他题目。
- 旧记录没有失败环节：界面使用中性说明，只建议确认登录并「检查登录」，不会断言凭据失效。

`auth_required`、`forbidden`、`changed_response`、`invalid_input`、`not_connected`、`unsupported`、`cleanup_failed` 会暂停自动尝试，等你处理后手动继续。其中：

- `changed_response` 表示平台返回结构或同步游标与预期不符，可能只是洛谷要求人工验证或网站结构变化，不一定是本地进度损坏。请先在普通浏览器确认账号能正常登录并通过验证，确认插件对当前平台响应和宿主版本的兼容情况后再重试；本地检查点会保留，不需要清空进度。只有当你确认平台数据与本地长期不一致、并且确实想重新核对全部历史时，才手动做一次「全历史完整核对」；不要把自动重试当成修复。
- `cleanup_failed` 表示旧凭据没能从 Windows 凭据管理器删除：再点一次「断开连接」，必要时重启 dsh。

「检查登录」是独立的一次探针：**成功只表示现在能登录**，不会撤销已经记录的同步失败，也不代表同步成功。

### 待补题目与手动处理

在洛谷同步面板展开「待补题目与手动处理（N）」（同一展开项下还有「已跳过 / 回收站」页签）。展开时只读取一页（默认 20 题，可切到 25 题），不会把整个积压拉下来。

每一行显示：题目编号（可打开原题链接）、本地已保存的标题（没有时显示「本地还没有标题」）、**逐题原因**（最近一次失败的原因、时间与累计失败次数）、以及「尚无逐题失败记录」这类中性说明。页面上「当前待补 N 题」是还没补齐资料的**题目键**数量；「历史失败尝试 M 次」是累计的**尝试次数**，同一题重试多次会累加，不是 M 道题。

- **重试此题**：只重试这一道题的公开资料，结果有三种——已补齐（离开待补列表）、暂不提供（平台不提供公开资料，例如个人题目，仍在列表）、失败（按固定分类显示原因，仍在列表）。不会自动连续重试，不会开始整轮同步，不调用 AI，也不改动历史覆盖、检查点、自动同步设置或计划。
- **手工补充**：把你自己确认的**标题与题面**写进本地记录。标题仅在本地还没有标题时需要填写，已有标题只读且不会被覆盖；题面为必填的真实题目描述（Markdown），不是填写“无法获取”备注的地方。点「保存到本地」才会提交，保存时会检查资料是否已在其他地方更新。表单明确写着：**仅补齐本地题目资料，不改变通过记录或自动确认标签；不使用 AI。** 提交成功表示用户提供的标题/题面写入本地并生成新的不可变快照，这一题离开待补列表；它**不代表**从平台抓取成功，也不保存平台标签或难度。若提交时快照已变化（例如另一处刚补过），提交会被拒绝，草稿保留，请刷新后重新提交。
- **跳过 / 移入回收站 / 恢复**：见下一节。

请不要在手工补充表单里粘贴 Cookie、会话或任何登录材料：这个表单只接受题目资料文本，补资料也不需要重新连接账号。

## 跳过、回收站与恢复

出题测试题、私有题或平台已删除的题目可能没有题面，不需要为它们填写虚构内容。展开「待补题目与手动处理 · 已跳过 / 回收站」，里面有三个页签：**待补题目**、**已跳过**、**回收站**。

| 操作 | 补题面队列 | 本地题库与统计 | 后续同步 | 恢复 |
| --- | --- | --- | --- | --- |
| 跳过 | 从该来源各账号队列中移除 | 保留已有题目、做题记录与统计 | 继续导入历史，但不再补齐此题资料 | 在「已跳过」恢复 |
| 移入回收站 | 从该来源各账号队列中移除 | 隐藏题目，排除对应提交与复盘的统计、新能力评估输入与新训练选题 | 原始记录可以更新，但不会重新显示或排队 | 在「回收站」恢复 |
| 恢复 | 若题面仍缺失，加入当前账号的待补队列 | 恢复使用保留的原始记录 | 恢复正常行为 | 无物理清空操作 |

- 每行可以单独操作，也可勾选本页后批量操作；跨页不保留选择，每次最多 50 题。确认区域会列出具体题号与影响范围，状态变化时整批拒绝，刷新后重新选择。
- 同一个洛谷站点上，该题的处理状态由所有本地账号共用；CF 等其他来源的同题记录独立保留。合并题库不再用被移入回收站的洛谷记录提供 AC 证据，但仍可展示其他来源的有效题目。
- 操作只写本地数据库：不改动平台、不调用 AI、也不需要 Cookie。恢复需要队列空间，队列满时保持原状态并显示原因，不会部分恢复。
- 旧的 AI 评估报告与已生成计划保留为历史快照；需要重新生成才能反映当前数据。账号级官方比赛评分与手工虚拟表现分不是这些题目的提交记录，不受回收站影响。

更完整的恢复/跳过取舍见[故障排查](troubleshooting.md)，题库侧的展示语义见[题库](problem-bank.md)。

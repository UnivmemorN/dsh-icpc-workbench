# Stage 32 — Luogu numeric tags and pending Codeforces mappings

## Problem and behavior

Version 0.1.24 could display names for Luogu numeric tags while its knowledge crosswalk still treated every numeric tag as an uncounted reference. Historical records containing only numeric tags therefore supplied no provisional knowledge evidence. Codeforces labels without a safe match were already retained with their own problem counts, but the diagnostic table was easy to miss.

Version 0.1.25 shares one unchanged 505-entry Luogu dictionary between the domain crosswalk and the UI. For the official Luogu source instances, a strict safe-integer tag ID resolves to the platform name, then passes through the existing conservative name rules. For example, `luogu-tag:53` resolves to 树状数组 and the Fenwick-tree technique; `luogu-tag:3` resolves to 动态规划 DP and only the DP category. The public payload at [Luogu's tag endpoint](https://www.luogu.com.cn/_lfe/tags) was checked again on 2026-09-15; all 505 pairs matched the 2026-09-14 snapshot. The moved table was also compared with the previous build, with no pair changed.

Raw identifiers and sources remain intact. Unknown IDs and names without rules stay explicitly unmapped; ambiguous and narrow labels retain their previous restrictions. Mirrors, alternate ports, foreign sources and explicit vocabulary overrides cannot borrow the official dictionary. Repeated submissions and an ID plus its textual name do not multiply a problem's knowledge count. The crosswalk version is `2026.09.15.1`; no taxonomy or database schema changed.

The knowledge page now shows a compact pending-label summary across all difficulty bands. “查看待核对标签” opens and focuses the existing table, enables issues-only, clears conflicting source/relation filters and returns to page one. Account changes reset this state. Unmapped CF labels retain their raw names, reasons and distinct attempted/solved counts; they do not block mapped labels on the same problem. Per-label counts cannot be added into a total problem count. The [CF Problem API documentation](https://codeforces.com/apiHelp/objects#Problem) remains a terminology reference, not a cross-platform equivalence claim.

These changes only affect provisional platform evidence and its presentation. They create no verified tag decisions, actual-method retrospectives or mastery claims, and require neither reimport nor AI calls. User guidance, developer mapping notes and third-party attribution were updated separately.

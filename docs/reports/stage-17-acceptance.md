# Stage 17 — 洛谷历史回溯与自动同步

版本：0.1.12（实验版），数据库 schema 7。施工使用独立插件工作区与 DeepSeek Harness 的 `deepseek-official/deepseek-flash`、max；协调端负责契约、复核、安装和 Git。宿主源码未修改。

## 实现范围

Windows 本地会话连接、检查、断开；提交历史首次回溯与断点续传；近 7 天重叠窗口的增量核对；用户触发的全部历史重新核对；每个账号独立设置自动同步、启动时运行和间隔。默认关闭自动同步，开启后默认 30 分钟，最小 5 分钟，仅在宿主运行期间生效。记录同步不调用模型。

实际记录 ID、提交时间、题目和判定写入原有提交存储，AC 参与已有统计与跨站同题展示。未知判定不会当作通过，AC 也不代表独立掌握了所有相关知识点。导入页面与断点、同步进度在同一事务中提交；资料补全失败保留真实提交，进入有上限、可重试的资料队列。不会为同步抓取题解。

会话仅保存到当前 Windows 用户的 Credential Manager。数据库保存不含凭据值的引用、进度与设置；写入前记录引用，崩溃恢复可清理未关联凭据；连接版本号在删除与重建后仍单调递增。原有匿名适配器继续用于旧入口，鉴权记录请求通过专用服务和来源节流。定时器、页面请求、连接操作与同步派工均在关闭时取消并等待完成。

## 限制与引用

**尚未完成真实洛谷登录态的历史同步验收。** 本轮合成响应遵循参考项目的 `data.records.result` 结构；洛谷不是为此插件提供稳定接口，实际返回结构或站点验证可能导致暂停。需要用户在完成的本地界面输入自己的会话进行验证，不能把合成测试描述为真实记录已同步。遇到登录、验证或结构错误时停止该账号的自动尝试；不实现验证码或站点挑战绕过。

最近 7 天的重叠窗口不能保证发现任意年代的重新评测；可主动重新核对全部历史。每次最多 20 页、每页最多 50 行，资料最多补全 10 题；部分回溯需继续或等待后续自动尝试。资料队列满时暂停继续翻页并先修复资料，避免遗失题目引用。全局平台请求限制在宿主启动时读取，修改后需重启；每个账号的自动同步设置即时生效。非 Windows 系统保留其余功能，但此版本无法保存洛谷会话。断开连接保留已导入的训练数据。

参考 [ZF3373/icpc-workbench 的洛谷适配器](https://github.com/ZF3373/icpc-workbench/blob/ac4a2e0920e07a9d5abde8cee54ac8aa8a3a5fa7/server/src/adapters/luogu.ts)，MIT，Copyright (c) 2026 ZF3373；独立实现，无上游源码或挑战处理代码复制。原 MIT 全文保留在 `licenses/icpc-workbench-MIT.txt`。判定含义核对了 [洛谷公开配置](https://www.luogu.com.cn/_lfe/config)，凭据层依据 [Windows Credential Manager](https://learn.microsoft.com/en-us/windows/win32/api/wincred/ns-wincred-credentialw)；完整来源见 [THIRD_PARTY_NOTICES](../../THIRD_PARTY_NOTICES.md)。用法见 [洛谷同步指南](../luogu-sync.md)。

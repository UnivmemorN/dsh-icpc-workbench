# Sprint Contract — ICPC Workbench v1

Status: initial repository created; implementation pending.

## Approved requirements
- Public repository UnivmemorN/dsh-icpc-workbench, independent workspace D:/dsh-icpc-workbench.
- Personal training, CF/Luogu/manual records first. Preserve raw difficulty and account history.
- Hierarchical algorithm/technique tags separated by solution. Analyze already-tagged problems too.
- Low-cost model reads editorials; reasoning role is used only for confirmed missing editorial, not auth/network errors.
- Located evidence + second verification + no conflict permit automatic adoption. Inference/conflict/weak evidence needs review.
- Preserve original tags and manual accept/reject choices; provenance and analysis version; immutable snapshots and stale-result checks.
- Default batch 20 problems, 50 analysis calls, 5 reasoning calls, concurrency 2; count retries, pause on quota, recover after restart.
- Workbench: today, problem bank/lists, review, weakness, plans, settings.
- Hide spoiler tags/solutions for unsolved work. Progressive hints, then explicitly requested full explanation/code.
- Distinct-problem statistics, minimum 5 problems before ranking weakness, show coverage/sample counts.
- Record independent vs assisted completion and actual solution used. Do not infer all solution skills from AC.
- Plans default 7 days and 60 minutes/day; real candidate IDs only, preview/adopt/edit/check off. Rule fallback without a model.
- Hydro student submission import is future work; test adapter/instance/domain/account design using a fake implementation.
- No judge, automatic submission, class administration, course library or contest calendar in v1.
- MIT attribution to ZF3373/icpc-workbench at 781e9f1981dba2822617e2cd13e92d6516f11b23.
- All platform IO is cancellable, rate-limited, and distinguishes permission, auth, rate limit, changed response, unavailable and no-editorial.
- CF API requests at least 2 seconds apart; checkpoints and idempotence.
- Package .tgz, clean install, host mismatch rejection, auth rejection, migration/backup recovery.

## Construction
Coordinator: scope, contracts, independent checks, commits/pushes.
Worker: installed dsh, deepseek-official/deepseek-flash, reasoning max.
One task/process at once; budget CNY 100, stop dispatch at conservative CNY 90.
Max 30 minutes and 40 main requests per invocation; at most two repair rounds for the same issue.
Worker runtime reports are local only. Do not publish credentials, private student data, editorial bodies, or model transcripts.

## Stages
0. GitHub initialization and SDK smoke.
1. Package skeleton, domain/application contracts, core rules and tests.
2. SQLite storage, task pipeline and recovery.
3. CF/Luogu/manual adapters and source fixtures.
4. Host API / LLM adapter / workbench UI and integration.
5. End-to-end acceptance, 30-problem manually checked tag benchmark and release.

## Acceptance
Type checks, architecture dependency checks, focused behavior tests, browser end-to-end, and packaged-install smoke.
30 manually checked problems: >=90% precision for automatically adopted tags; report recall and adoption coverage too.
Live platform/model verification is separate from offline fixtures. Missing verification remains explicit.

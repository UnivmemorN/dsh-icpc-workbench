# 洛谷账号连接与同步

本页说明如何在「账号与同步」里连接自己的洛谷账号、同步提交记录，以及这一功能的限制与生命周期。
每一步都只使用本机 dsh 提供的类型化业务接口；浏览器界面不会直接访问洛谷，也不会读取或保存模型凭据。

## 入口

1. 打开 **账号与同步** 页面，选中洛谷账号；数据来源会跟随账号。
2. 页面里的 **洛谷账号连接与同步** 就是连接入口（完整路径：账号与同步 → 数据来源：洛谷 → 导入与同步 →
   洛谷账号连接与同步）。默认只显示一张紧凑卡片：连接状态、最近一次登录检查、历史覆盖、题目资料积压与
   自动同步状态，以及主要的「开始 / 继续同步」（只有本轮在运行时才出现「暂停本轮」）。
3. 面板需要一个**当前账号**：如果「当前账号」还不是洛谷账号，请先用「添加账号」按数字 UID 新建一个洛谷账号，
   或用页面上方的账号列表选中已有的洛谷账号。未选账号时，面板只显示指引，不会发起任何请求。
4. Cookie 输入框、详细进度、自动同步设置与高级操作默认收起，分别由「连接洛谷 / 更新登录凭据」、
   「同步详情」、「自动同步设置」和「高级操作」按需展开；关闭卡片上的展开项不会保存或修改任何设置。

## 连接步骤

凭据输入框默认收起：点唯一的「连接洛谷」（已有连接记录时显示「更新登录凭据」）才会展开表单；关闭表单、
切换账号或提交后，输入框会卸载并清空；切换输入方式也会清空已填内容。收起整个洛谷面板同样会关闭并清空凭据表单。表单里提供两种输入方式，
默认只需要复制一项：

1. 在你平时使用的浏览器中登录洛谷。
2. 按 F12 → **Application（应用程序）→ Storage → Cookies → https://www.luogu.com.cn**。
3. 找到 **__client_id**，只复制 **Value（值）** 一列，粘贴到工作台「__client_id 的值」输入框。
   上方只读的 **_uid** 来自当前账号的数字 UID，请核对它与浏览器 Cookie 中的 _uid 相同；若不同，先切换当前账号。
4. 点「连接」。输入框在提交、切换账号、切换输入方式、关闭表单或离开页面时清空。
5. 「检查登录」会使用已保存的凭据做一次实际读取。

表单里只保留一行 F12 → Application/Cookies → Value 的简短说明和一句“只在本机使用”的提示；
完整的步骤、`_uid` 与 `__client_id` 的区别、整段 Cookie 的取舍、内存与存储说明都在表单内唯一的
**「如何获取 Cookie」** 展开项里。

可选：勾选「高级：粘贴整段 Cookie」，再从 F12 → Network（网络）→ 洛谷请求 → Request Headers（请求标头）复制 Cookie 完整值。
可带 Cookie: 前缀；程序只保留 __client_id 与 _uid 两项。__client_id 是会话标识，_uid 是账号编号，两者不能互相替代。

**规范化不等于绕过平台校验**：本工作台只把自己发出的 `record/list` 认证请求规范成 `__client_id` 与 `_uid`
两个 Cookie，并丢弃其余 Cookie；这不会绕过、也不能保证通过洛谷自身的校验。即使凭据有效，平台仍可能返回
人工验证页或直接拒绝访问，界面会按固定错误码说明这一步的失败。

**旧凭据仍然可用**：在本版本只保留两项之前保存过的整段 Cookie 会继续可用——每次读取时都会在本地按同一
规则规范化成两项，不需要为了兼容而重新连接，也不会把旧值原样发出去。

**不要把 Cookie 或 `__client_id` 粘贴到 AI 对话、聊天群或任何在线服务**：那等同于把账号登录权交给对方。
本插件也从不把登录材料送进模型请求。

## 凭据保存在哪里

- 登录凭据只发送给本机 dsh 的洛谷连接操作，保存在 **Windows 凭据管理器**（按工作台数据目录隔离的命名空间）。
- 它不会写入 `localStorage`、通用设置、备份、日志或 AI 请求；状态与错误信息也不会回显凭据内容。
- 同步状态、错误文案与界面提示都只包含非秘密字段（连接状态、时间、计数、固定错误码）。
- 「断开连接」**只删除本机保存的登录凭据**：已经同步到本地题库的题目、提交记录、材料与统计全部保留。

## 当前系统支持

- **Windows**：受支持，使用 Windows 凭据管理器。
- **Linux 等没有受支持凭据后端的系统**：`luogu.status` 会报告 `connectionAvailable: false`（并给出平台名），
  「连接 / 检查登录 / 断开」返回固定的 409 文案且不触碰任何存储；账号、题库、JSON/CSV 导入与 AI 功能仍然可用。

## 同步操作与状态含义

| 操作 | 实际语义 |
| --- | --- |
| 开始 / 继续同步 | 提交一次同步预留：有未完成的进度就从中断处继续；否则按最近窗口增量拉取。一轮最多提交 20 页（每页 50 行）与 **100 条题目资料**，剩余留给下一次。这条路径只调用洛谷平台接口，**不调用 AI 模型，也不消耗 AI 额度**。 |
| 补齐全部积压资料（不使用 AI） | 只处理点击时已经存在的题目资料积压：逐个请求洛谷公开题目数据，开始时已有的积压每题只尝试一次，做完就停；不读取提交历史，也不改动历史覆盖、检查点、自动同步设置与计划。按来源整体限速，每个请求之间至少间隔 2 秒，积压较大时可能需要几十分钟；进度按题保存，可以离开页面，但 dsh 需要保持运行；「暂停本轮」会保留已完成的进度。 |
| 全历史完整核对 | 显式重新扫描这个账号的全部历史（需要先勾选确认）。它会更新「历史覆盖」，完成前历史覆盖仍显示为未完成。 |
| 暂停本轮 | 只暂停**当前这一轮**：已经提交的进度保留，可以稍后继续。它不会关闭自动同步。 |
| 自动同步开关 | **按账号**决定以后是否自动运行；默认关闭。与「暂停本轮」是两件独立的事，两者互不替代。 |

面板把三种事实分开显示（全文在「同步详情」里；收起时卡片只给同一事实的短句）：

- **历史覆盖**（`historyComplete` / `historyCompletedAt`）：是否完成过一次全历史核对；
- **最近一次尝试**（失败码、失败时间、重试时间）：这次尝试的诚实结果；
- **题目资料积压**（待补题目数、已补、失败）：补齐**题目资料**的进度；这条补资料路径只抓取题目元数据与题面，从不抓取题解，
  也不调用 AI 模型。普通同步每轮最多补 100 条，剩下的留给下一次；积压较多时用「补齐全部积压资料（不使用 AI）」一次处理当前积压，
  它不读取提交历史，也不改变历史覆盖、检查点与自动同步计划。积压大小只是本地还没补齐资料的题目键，与「是否有提交记录缺失」是两件事。

卡片收起时也会用一句话说明失败或暂停（含失败环节），并指向「同步详情」；「同步详情」里每种长句只出现一次。
「检查登录」成功只表示**现在**能登录：它不会撤销仍然存在的同步失败，也不代表同步成功，两者在界面上始终分开。

处理计数（`submissionsSeen` / `pagesInPass` / `totalPages`）表示**处理过的行**，包含重复核对与平台重判复查，
**不代表新增提交或新增通过**。平台上的「已通过」只是外部证据，不等于你独立掌握了解法。

## 最近窗口与完整核对

- 增量同步只覆盖**最近窗口**：窗口起点是上次成功扫描开始时间减去 **7 天重叠**，用来刷新刚发生改判的记录。
- 更早以前的任意重判不会被增量同步发现，必须显式做一次**全历史完整核对**。
- 完整核对会重新扫描全部历史，耗时更长，但不会删除已有记录；完成后增量窗口重新开始。

## 自动同步与本地主机生命周期

- 自动同步**只在 dsh 打开时**运行：宿主每 60 秒检查一次到期账号，关闭 dsh 后不会同步。
- 每个账号的开关、启动时同步一次、间隔（5–1440 分钟）都是持久设置，保存时带**设置版本（CAS）**：
  如果设置已在别处变化，保存会被拒绝并提示刷新，而不是覆盖别人的决定。每账号设置**立即生效**。
  这些设置在「自动同步设置」里维护：字段始终可以修改（只有操作进行中或插件关闭时才锁定），
  只有确实改动过某一项后「保存自动同步设置」才可点；仅展开这一节不会修改或保存任何设置。
- 全局平台限速（`platformLimits`）在插件激活时快照，**修改全局限速需要重启 dsh** 才对洛谷来源生效。
- 一轮同步至少持有 **120 秒**租约：如果单个页面的请求预算更大（重试次数 × 请求超时 + 限速间隔），租约会自动延长到覆盖它，
  并在每提交一页后续租；进程异常退出后租约到期即可恢复。错误码 `lease_lost` 表示租约被别的实例接管。

## 可恢复性与失败处理

- 每一页的提交（页数据、进度、检查点）在同一个事务里完成，所以中断不会留下半页数据。
- 补齐积压资料时**每题**提交一次进度，并在每次平台请求前续租：可见的积压会在运行中不断减少，中断或关闭 dsh 也不会丢掉已经补完的题目。
  一次资料补齐不会超出 120 秒租约（`defaultLeaseMs` 覆盖单次请求与重试预算），一旦租约被另一个实例接管就立即停止，
  不再发出请求，也不会覆盖对方的记录；没补完的键留在积压里，之后可以继续。
- `resumePending: true` 表示还有可继续的持久进度；重新打开面板会显示同一状态，**重新挂载界面不会清空或重启正在运行的任务**。
- 失败只以固定错误码集合呈现，并给出下一步动作；其中 `auth_required`、`forbidden`、`changed_response`、
  `invalid_input`、`not_connected`、`unsupported`、`cleanup_failed` 会暂停自动尝试，等你处理后手动继续。
- 如果出现 `changed_response`（平台返回结构或同步游标与预期不符）：它可能只是洛谷要求人工验证、或网站结构发生了变化，
  不一定是本地进度损坏。请先在普通浏览器里确认账号能正常登录并通过验证，再把 dsh 更新到兼容版本后重试；本地检查点会保留，
  不需要为了重试而清空进度。只有当你确认平台数据与本地长期不一致、并且确实想重新核对全部历史时，才手动做一次「全历史完整核对」；
  不要把自动重试当成修复。
- 元数据积压上限是 2000 条，达到上限属于**背压**：同步会先停止拉取新的历史页而不是丢弃题目键
  （`backlogDropped` 恒为 `0`）；继续同步会优先整理积压，也可以用「补齐全部积压资料（不使用 AI）」一次处理当前积压
  （最多 2000 个不同的键，每个键只尝试一次）。

### 失败发生在哪一步

一轮同步分两步：先读取**提交记录**（需要登录的认证请求），再补齐**题目资料**（公开题目数据，匿名读取）。
两步都可能返回同一个错误码（例如 `auth_required`），所以新写入的失败记录会额外保存失败环节（`stage`）：

- `stage: metadata`：失败发生在**补齐题目资料**这一步，是题目资料补齐失败；**不代表保存的登录凭据已过期**，
  重新连接也不能解决它。已经同步的提交记录、历史覆盖与检查点都会保留，待补题目资料会继续排队，
  可以稍后手动继续同步。自建或私有 U / T 类题目可能无法匿名读取；受限题保留待补并继续处理其他题目。
  公开题访问受限、限流或页面异常仍会暂停。`U` / `T` 编号不意味着题目一定私有
  （2026-09-14 核对 <https://help.luogu.com.cn/manual/luogu/problem/>）；这条补资料路径始终是匿名读取，
  不会改用登录凭据，也不调用模型。
- `stage: history`：失败发生在**读取提交记录**这一步；若错误码为 auth_required，表示这次认证读取被平台要求重新登录，
  请先点「检查登录」核对当前登录，再按提示手动继续。
- 旧记录没有 `stage`：界面使用中性说明，只会建议你确认登录并点「检查登录」，不会断言凭据已经失效。

「检查登录」是独立的一次连接探针：如果它在这轮失败**之后**成功，面板会显示“当前登录可用”，
但这只说明现在能登录，**并不代表同步成功**；已经记录的同步失败仍然保留，自动同步也仍然按该失败的规则暂停或重试。

## 真实账号验证的限制

自动化测试使用合成传输、合成凭据库与临时 SQLite。当前版本的本机真实连接验收见 [发布验收](reports/stage-19-acceptance.md)。
一次登录检查只验证该时刻的提交记录读取，不证明题目资料补齐、所有页面或今后的会话有效期。

## 没有连接时怎么办

不连接也可以继续用原来的 JSON/CSV 手工导入（见 [手工导入格式](manual-import.md)）。连接面板只是新增一条更省事的路径，
没有替换任何既有导入功能。
